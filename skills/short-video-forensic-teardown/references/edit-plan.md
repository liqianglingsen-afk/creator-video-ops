# 短视频剪辑方案与复评

新综合评分、剪前保护和复评须同时执行[0.5 封面、前三秒与镜头取舍](creative-evidence.md)。

涉及优化建议或改后复评，采用 [0.4.0 全片方案与对照验收](full-revision.md) 的预测、保留资产、版位与报告约定。历史报告沿用生成时的口径。


最低优化目标为 85/100。更高目标按任务要求执行。先标出当前版本、评分口径、实得分、目标和差距。内容拆解用十维量表；后期技术质检用同一 Framecheck 预设和抽样参数对照。两项都委托时分别验收。播放、成交或留存效果需要发布数据验证。

## 先试剪手头的素材

1. 盘点成片、原始镜头、可用同期声、独立音轨、字幕和已有产品图。标明哪些已拿到、哪些只是设想。只有压制成片时，把烧录字幕、混音和裁切空间计入限制。
2. 对照扣分证据，优先保留最有说服力的原声、动作和可读画面。按影响和实施成本排序，先考虑删停顿、调镜序、现有特写覆盖、修字幕、调混音。重排须保持事件因果和声画含义。把起止点放在原句、动作、音乐合适的位置。
3. 以实际素材名编写剪辑单。每项写清源入出点、成片入出点、轨道、操作和参数、处理哪项扣分、怎样验收。全片处理写明全片和时长，删除项写明成片切点。烧录字幕的替换要说明遮盖或重构方法。附能被 Codex 直接运行的命令、脚本或可导入工程，填入真实输入输出及依赖；需要剪映人工完成的个别项写清步骤。参数作为试剪起点，依据回看调整。
4. 要求优化或试剪时，在独立输出目录生成新版本。用 ffprobe 核对时长、画幅、音轨、帧率，回看剪点、台词、字幕、产品读数和尾帧；按原量表与同一预设复评。仅要求分析或只给参考片时，交付方案并注明改后待评。原版已过线且没有值得改的项目，可直接结案。

例如单条素材有声，已确认 2.0–3.2 秒是可删停顿时，可从两轨同时剪除这段，新的 2.0 秒处连上原片 3.2 秒。实际项目用原片名和核准的时间点替换示例。检查连接处音节完整、动作连贯，成片缩短 1.2 秒。

```sh
ffmpeg -n -i input.mp4 -filter_complex "[0:v]trim=end=2,setpts=PTS-STARTPTS[v0];[0:a]atrim=end=2,asetpts=PTS-STARTPTS[a0];[0:v]trim=start=3.2,setpts=PTS-STARTPTS[v1];[0:a]atrim=start=3.2,asetpts=PTS-STARTPTS[a1];[v0][a0][v1][a1]concat=n=2:v=1:a=1[v][a]" -map "[v]" -map "[a]" -c:v libx264 -crf 18 -c:a aac -b:a 192k -movflags +faststart cut-v1.mp4
```

## 什么时候补素材

已有镜头无法证明关键主张、找不到能辨认的主体或必需原声，或试剪复评仍低于目标且残留扣分无法靠剪辑解决时，写明已检查的素材、时间点、已试方法或无法试剪的原因、差距。先考虑改用现有证据支持的表述；需要新内容才提出增补、重做、重拍。逐项给最小补拍单：缺哪条证据、谁准备什么、机位/景别、动作或台词、建议秒数、光线/收音、接入成片的位置和验收画面。能做的剪辑继续交付。补齐后按同一口径复评；尚无证据时标为待核。

## HTML 约定

沿用模板的可见数值与剪辑表。新报告标明 `rubric-version` 为 `creative-100-v1`，十行 `score-row` 依次填写维度、权重、实得分、依据与修改优先级。权重和实得分使用纯数值。用 `data-contract="optimization-target"` 标记目标，`raw-score` 标记已按单项上限计分的十项合计，`current-score` 标记再应用总分封顶后的精确值。有总分封顶时填写 `overall-cap` 及原因。证据不足以出分时相应分项、合计和当前分写“待核”。旧版报告沿用原分母。`edit-route` 取“试剪现有素材”“需补充素材”“当前版本已达标”或“证据不足待核”。每个 `tr[data-contract="edit-step"]` 依次给五个非空单元格：源素材与时码、成片位置、执行操作与参数、对应扣分、验收。用 `edit-execution` 标记可运行命令或有效本地脚本/工程链接。走补素材分支须填 `edit-limit`（剪辑为何不足）及 `pickup-brief`（具体补拍单）。可保留的原版或证据不足时说明依据，不虚构操作。
